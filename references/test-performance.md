# 测试提速审核与验证

当前生产验证使用 Go：`npm run test:kernel`。局部筛选和源码绑定规则见 [架构与开发说明](architecture.md#并行开发与验证)。以下保留 2026-11-15 至 2026-11-16 的历史测量，旧 Node 内核入口和结论不代表当前生产路径。

## 范围

2026-11-15 审核《Gitowl-完整冒烟与验收测试提速优化方案》，验证持续至 2026-11-16。本轮修改测试准备、测试筛选、源码取证和构建缓存，不修改原内核业务行为，不生成固定测试安装器。

方案找到了真实开销，但其“完整流程缩短 95%”等数字是预估，不是本轮已验证的结果。下列测量不能相加推算整套流程的收益。

## 已实施

- 仓库检查合并为批量忽略规则、批量对象信息和流式 blob 读取。常规检查使用 5 个 Git 进程，不再随文件数启动新进程。正文读取仍受 10 MiB 限制；缺失对象、大文件、凭据、非法编码、暂存忽略规则和链接检查不降级。
- 源码取证只在单次快照内复用父目录检查，以 16 个文件为一批读取。结束前重新检查目录。每次仍读取实际文件字节，保留索引树、子模块、环境摘要和证据校验。
- 工作台、操作弹窗和仓库弹窗的测试各自准备独立模板，再复制到每个用例的独立目录。操作弹窗复制后重设自身的 hooks 路径。真实 Git、Store 和 Dispatcher 仍参与测试。
- 重型辅助提交测试按 TypeScript 解析得到的项目导入关系筛选，覆盖传递依赖、动态字符串导入和循环。共享运行器、声明、锁文件和动态夹具仍触发全量；解析不完整时明确提示并全跑。未把整个 Store、Model 或 Git 目录当作依赖。
- 补齐 Copilot 辅助提交等测试的名称匹配。原生生成和其他普通测试不随这些重型套件跳过；显式文件参数及 GITOWL_UNIT_ALL=1 仍可强制执行。
- 开发内核与生产内核入口只执行五类真实内核集成测试。纯 Go 单测由独立入口执行，不再在两个内核入口重复全跑。结果校验同时要求真正的内核用例通过，不能只凭进程退出码或单实例测试通过。
- 设置测试每个语言、主题、页面读取一次真实内核状态，再遍历字号和窗口大小。页面矩阵从 324 次选择降为 54 次，保留全部 324 个布局组合及供应商表单断言。
- 原生生产构建不再编译随后会被删除的兼容 renderer。普通上游构建仍保留它；main、native-kernel、crash、CLI 和 highlighter 均保留。
- 开发和生产 Webpack 使用被忽略的本地文件缓存，按目标与构建模式隔离。测试验证了模块复用、源码变化和编译身份变化后的失效。
- 运行时缓存不再读取 app/test 或无关参考文档；实际导入的菜单 JSON 仍参与摘要。保留生产输出、许可证和锁定输入的逐字节核验。
- 脚本套件不再重复启动专用生产运行时冒烟，文件并发设为 2。专用运行时冒烟和各真实内核用例仍执行。
- 经确认后修复四个原有差异面板测试：文件选择与面板展开分开操作，并等待新差异响应。保留布局、行号、草稿、选中项及取消/失败恢复的原有断言，不改业务代码。

## 未照搬的建议

| 建议 | 审核结论 |
| --- | --- |
| 从运行时摘要直接移除 Git 提交号 | 不采用。app/app-info.ts 将其注入 __SHA__，它确实影响输出。Webpack 自身会按 DefinePlugin 值使相关模块失效。 |
| 仅按 assisted-commit / copilot 文件名前缀确定源码影响 | 不采用。共享 Git、Store、Dispatcher 和模型可能影响这些测试。改用实际导入关系。 |
| 用 git status 和索引树代替前后源码字节校验 | 不采用。已脏文件再次改变时，状态、大小、时间戳和索引都可能不变。新增回归覆盖这种情况。 |
| 缓存命中就无条件跳过运行时冒烟 | 不采用。构建回执在冒烟之前写入，不能证明上一轮冒烟成功。运行时检查还涉及真实进程、Git 和 Copilot/Koffi，不只是静态文件检查。 |
| 一并跳过 Sass 校验 | 不采用。crash.css 仍是交付资源；现有校验会扫描实际存在的样式表，不要求 renderer.css 存在。 |
| assisted-commit 的 seed 每次执行多次 git init | 原因不成立。它调用的 setupEmptyRepository 已直接建立空仓库结构；本轮只替换确实反复执行初始化命令的原生流程夹具。 |
| 直接共享所有 Electron 实例或机械拆分重型文件 | 本轮不采用。现有用例使用可变进程级 mock、配置和恢复状态，需要先拆清隔离边界，不能直接并发共享。 |
| 删除旧 native-service 研究入口 | 本轮不做。它不在当前默认单元测试或原内核冒烟路径中；没有用删除历史对照代码换取未经测量的收益。 |

| 检查对象 | 修改前 | 修改后 | 核对结果 |
| --- | ---: | ---: | --- |
| 仓库检查，3,813 个暂存文件 | 622.05 秒 | 1.07 秒 | 同一索引，两次均通过；新增测试约束进程数量不随文件数增长。 |
| 源码快照，6,147 文件、4 个子模块 | 12.90 秒 | 2.63 秒 | 旧实现与新实现返回的完整 JSON 完全一致。 |

三个原生仓库流程文件的 53 项测试在修改前后均通过。整组挂钟测量分别为 175.38 秒和 236.32 秒；后一次同时存在其他生产构建，不能据此宣称整组提速。上表只报告独立准备阶段的收益。

初次脚本验证还发现系统 npm 11.11.0 不满足项目的 npm >= 11.17.0 要求，Koffi 安装策略用例单独执行也失败。使用已锁定的 Node.js 24.22.1 / npm 11.19.1 后，该用例通过；未改断言或忽略失败。

四个原有差异面板失败使用 Go overlay 在未修改的 3a4ba8bb701b5c7e7e44b8ddb61443c486e75f74 基线上复现。修复后按原测试名称单独执行，四项均通过。完整单测还需要 PowerShell 7 可被 PATH 找到；本次使用现有的 PowerShell 7.6.9，四种 shell 的环境测试均通过。

## 运行方式与边界

使用 third_party/native-runtimes.json 对应的工具链，通过已有入口执行：

先确认 Node.js 与运行时登记一致、npm 满足 package.json 要求，且 pwsh 可以执行。不要等长时间单测启动后才补这些前提。

- npm run test:repo：仓库检查回归。
- npm run test:script -- --test-concurrency=2：脚本、缓存与取证回归。专用运行时冒烟在此有意不启动。
- npm run test:kernel：开发原内核及其原生适配集成测试。
- npm run test:kernel:production：生产运行时准备、专用冒烟及生产内核集成测试。
- npm test：按真实依赖选择重型辅助提交测试；设置 GITOWL_UNIT_ALL=1 可全跑。

生产缓存复用仍检查输出字节。修改源码、资源、锁文件、编译参数或许可证后不得手工伪造回执。保留完整测试的失败退出码和被跳过项目的实际记录。
